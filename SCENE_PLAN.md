# План композиции scene-v3

Актуальная смысловая политика: фраза задаёт замысел, а не обязательную буквальную
сцену. ИИ выбирает ближайшую подходящую выполнимую композицию, вправе менять детали,
количество, связи и состав, и объясняет существенную адаптацию в explanation.
Жёсткими остаются только технические ограничения ТЗ и целостность выбранного плана.
Relations проверяют выбранную интерпретацию, не точное соответствие исходной фразе.

Адаптер API принимает однозначные варианты записи: nextTo/next_to/beside/adjacentTo
→ near, snake_case канонических типов, target → targets, from/to → subject/targets.
Неоднозначные/неизвестные правила не удаляются. Отдельное правило on удаляется лишь
как избыточное, когда его subject/target точно совпадают с уже заданным item.on;
иначе план отклоняется. Ошибка показывает индекс, поле и безопасное название типа.

При ошибке формата или геометрии даётся одна попытка исправления: максимум два
API-запроса на сборку, до 45 секунд ожидания каждого. В повторный запрос входят
та же метафора и локальное замечание проверки, без SVG и документа. Сетевые ошибки,
таймаут, неверный ключ, лимит и явный отказ модели не повторяются автоматически.
Обе попытки выполняются до создания фрейма; при неудаче документ остаётся прежним.

Поставка первой части расширения этапа 6. ИИ возвращает готовые настройки сцены,
не только уникальные типы предметов. Личная база рецептов — следующий шаг после
проверки этого контракта, пока не реализована.

Пример: [catalog/scene-plan.example.json](catalog/scene-plan.example.json).
Он описывает ровно пять экземпляров: три книги, телефон на первой, монета на второй.
Третья книга без дочернего предмета. Фоновый дубль в режиме ИИ не добавляется.

## Контракт

Объект ответа API содержит ровно `status`, `items`, `relations`, `explanation`.
Прежние scene-v2 JSON без relations поддерживаются только локальным исполнителем
для совместимости примеров/старых данных; новый ответ API обязан содержать relations.
Для `status: unsupported` массив items пуст. Для ok — 1–8 экземпляров:

| Поле | Правило |
| --- | --- |
| instanceId | Уникальный i1..i8 |
| assetId | Разрешённый ID библиотеки; может повторяться |
| x, y | Числа 0.05..0.95: нормализованный центр на холсте для самостоятельного объекта |
| rotation | Любое конечное число от −180 до 180°, поворот целого SVG |
| layer | Уникальное целое 0..7, снизу вверх |
| on | null либо instanceId книги/папки на более низком слое |
| state | main/background, цветной/монохромный; у старых планов можно опустить |

Правила relations — до 24 объектов с ровно type/subject/targets. subject и targets
ссылаются на разные существующие экземпляры. Для between/centeredBetween/equalDistance
нужны две цели, для centered/centeredX/centeredY — пустой массив, для остальных одна.
Общий реестр 24 типов и числа целей — SCENE_RELATION_TARGETS в scene-plan.ts;
он используется валидатором, адаптером синонимов и передаётся в системный промпт.

| type | Проверка после расчёта сцены |
| --- | --- |
| leftOf / rightOf | Центр левее/правее цели минимум на 2% ширины |
| above / below | Центр выше/ниже цели минимум на 2% высоты |
| between | Проекция на отрезок целей 10–90%, отклонение от линии ≤6% в нормализованных координатах |
| near | Нормализованное расстояние центров ≤0.40 |
| alignedX / alignedY | Одна вертикаль/горизонталь, отклонение ≤2.5% |
| inFrontOf / behind | Слой выше/ниже цели; само по себе не разрешает перекрытия |
| tiltedToward | Левый наклонён на +1…60°, правый на −60…−1°; верхушки направлены к центру |
| farFrom | Расстояние центров ≥0.45 |
| centeredBetween | Проекция на отрезок целей 45–55%, отклонение от линии ≤6% |
| equalDistance | Разница расстояний до целей ≤0.025; цели разнесены минимум на 0.10 |
| diagonalTo | Центры разнесены минимум на 8% по обеим осям |
| sameRotation / oppositeRotation | Разница углов 0°±2° / 180°±5°, только в плоскости |
| alignedLeft / alignedRight | Совпадение левых/правых границ с допуском 2.5% ширины |
| alignedTop / alignedBottom | Совпадение верхних/нижних границ с допуском 2.5% высоты |
| centeredX / centeredY / centered | По центру ширины / высоты / обеих осей, допуск 2.5% |

Конструктор уточняет edge-выравнивания, центрирование и centeredBetween при каждом
подборе общего масштаба. Самостоятельный subject перемещается со своими дочерними
предметами на опоре. Дочерний subject отдельно не перемещается; его положение
по-прежнему задаётся on-координатами. Противоречивые правила не отбрасываются:
после ограниченного числа проходов вся геометрия и все связи проверяются.
Границы — AABB повёрнутых контейнеров, не реальные края видимых контуров.

Все canonical-имена принимаются также в snake_case. Дополнительно: align_left →
alignedLeft, center_x → centeredX, midpoint_of → centeredBetween, equidistant →
equalDistance, horizontal_alignment → alignedY, vertical_alignment → alignedX.
В промпте предлагается обычно 1–5 нужных правил, а не все отношения сразу.
Четыре встроенных примера покрывают наклон, центр, колонку и среднюю точку.

«Лицом друг к другу» трактуется как tiltedToward, с явным пояснением этой плоской
интерпретации. Исходный ракурс не меняется. Новая сторона/зеркало/3D не создаются:
ИИ выбирает смысловую альтернативу и объясняет её, либо возвращает unsupported,
если разумного варианта нет.

Готовые инструкции и пример — catalog/ai-composition-rules.json; сборка включает
их в системный запрос. Это расширяемый общий справочник правил, а не личная база
и не дообучение модели. Явный rotation теперь может быть 90/180°, прежняя политика
малых углов в catalog/rotation-policy.json сохранена для автоматической сборки 5A.

При заданном on координаты x/y относятся к локальной системе опоры: (0.5,0.4)
означает центр по горизонтали и 40% высоты опоры. Дочерний предмет целиком помещается
в повёрнутый прямоугольник опоры, не получает отдельного масштаба. Вложенные стопки
и опоры других типов пока не поддерживаются. Два ребёнка одной опоры должны быть
разнесены; перекрытие разрешается только непосредственной паре ребёнок–опора.

У модели нет изображений: on — размещение по нормализованным координатам и границам,
не распознавание реальной поверхности страницы и не физическая симуляция.
Поддержка произвольных связей вроде «внутри», «держит» или многоэтажных стопок
не заявлена; невозможный план отклоняется.

## Выполнение

scene-plan.ts проверяет схему, ID, количество, слои, ссылки, разрешённые опоры,
размеры и повороты. Подбирает один общий масштаб двоичным поиском по границам
для нескольких вариантов расстояний между группами и свободных раскладок (ряд,
колонка, сетка). Нормализованные координаты ИИ — начальное предложение, не жёсткие
якоря. Дополнительно проверяется равномерное увеличение всей группы с центрированием.
Пропорции, экземпляры, повороты, состояния, слои, опоры и все relations сохраняются.
Оценка выбирает вариант по заполнению, балансу и читаемости; площадь предмета на
опоре не считается дополнительной занятой областью. Локальный подбор не обращается
к API. При жёстко заданном ряде на высоком холсте пустое место может быть неизбежно.
Проверяет поля,
наложения независимых объектов и полное вмещение ребёнка в прямоугольник опоры.
Слишком мелкий или неисполнимый результат отклоняется до создания фрейма.

Имена экземпляров в Layers содержат i1..i8. ochen-interpretation сохраняет исходный
план и его версию; ochen-recipe-instance/on — происхождение узла. Это не текущий
рецепт после правок: ручной сдвиг опоры не перемещает ребёнка автоматически,
дублирование/удаление не переписывает исходный план. Для личной базы потребуется
отдельная сериализация актуальной сцены с новыми уникальными ID и проверкой связей.

Режимы цветной/смешанный/монохромный применяются локально. В этой ветке порядок
слоёв из плана имеет приоритет: монохромный ребёнок остаётся над своей опорой.
Настройка шаблона и фоновый дубль относятся к сценарию названий и в режиме ИИ
отключены. Обычная компоновка 5A по названиям продолжает работать отдельно.

Каждая сборка и «Новый вариант» в режиме ИИ запрашивают новый план с seed и
форматом холста: расходуют квоту. Повторяемость самой языковой модели не гарантируется.
Исполнение одного и того же проверенного JSON и настроек детерминировано.

Во внешний запрос входят текст, каталог ассоциаций, числовые размеры/разрешённые
углы исходников выбранной L/S и размер холста/seed. SVG, paths, превью, примеры,
документ, настройки палитры и чужие объекты не отправляются. Ключ — только авторизация.

## Проверка

Автотесты используют подготовленный JSON: пять экземпляров, правильные опоры,
L/S, три формата и три режима состояний; дополнительно — неверные ссылки, циклы,
слои, наложения, неизвестные ID и запрещённые углы. Это проверка исполнителя,
не доказательство, что реальная модель каждый раз правильно поймёт количество и связи.

`npm.cmd run preview:ai-scene` после сборки создаёт out/ai-scene-example.html.
Локальные рендеры примера просмотрены в L/S и трёх форматах. Реальный ответ API
нужно проверить в плагине с личным ключом, начиная с исходного запроса владельца.
