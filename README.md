# Ochen Composer

Плагин Figma Design автоматически собирает композиции из фиксированной библиотеки
предоставленных SVG. Исходный файл библиотеки/аккаунт владельца для запуска не нужен.

- [Требования и покрытие](REQUIREMENTS.md)
- [Итерации и приёмка](ITERATIONS.md)
- [Технический план](DEVELOPMENT_PLAN.md)

## Текущее состояние

Реализованы названия/синонимы, отдельные L/S, три формата/схемы, seed, общий масштаб,
автоматические допустимые повороты, состояния и команды правки из панели.
3B подтверждена владельцем, 3C реализована; переход к 4 разрешён. Этап 4 готов к приёмке.
Три палитры, пользовательский JSON и перекраска реализованы. Скачивание SVG из панели и метафоры ещё впереди.
До метафор отдельно обсуждаем подход; AI не обязателен.

## Сборка и запуск

1. Node.js 22+: `npm ci`.
2. `npm run build` упаковывает SVG и собирает `code.js`.
3. Figma Desktop → Plugins → Development → Import plugin from manifest → manifest.json.
4. Откройте редактируемый документ и запустите OchenComposer.

После изменений перезапустите плагин; повторно импортировать manifest не требуется.
`npm run watch` отслеживает assets/catalog и TypeScript. Изменения ui.html требуют
перезапуска плагина. `npm run lint` / `npm test` — автоматические проверки.
Текущая версия не использует сервер, сеть и API-ключи.

## Сборка композиции

На вкладке «Сборка» введите названия через запятую/перенос строки, до 8 предметов.
Повтор названия создаёт экземпляр. Неизвестное название блокирует частичную сборку.
Примеры: «Книга, телефон, монета», «Телефон, наушники, монета», «Лампа, книга, цветы».

L/S — детализация; формат холста выбирается независимо. Все предметы и дубль
используют общий масштаб исходников 1×. Повороты задаются данными rotation-policy.json;
лампа и цветы остаются вертикальными. Seed воспроизводит план, «Новый вариант»
создаёт отдельный фрейм с новым seed, не удаляя ручные правки старого.

Режимы: цветные / смешанные / монохромные. Дополнительный монохромный дубль
включён по умолчанию и отключается. Для сцены без монохромных предметов выберите
«Цветные» и отключите дубль.

## Правка композиции — приёмка 3C

Выберите сцену или её предмет. Выбор одного предмета открывает вкладку «Правка».
Можно выбрать внутреннюю деталь: команда нацеливается на полный исходный предмет.

- Стрелки сдвигают на 10 px.
- Поле угла задаёт абсолютный угол по часовой стрелке вокруг текущего центра.
  Положительное значение здесь может иметь противоположный знак относительно Rotation Figma.
- «Дублировать» сохраняет текущую графику, масштаб, состояние и угол; находит свободное место.
- «Удалить» убирает только выбранный экземпляр.
- «На слой выше/ниже» меняет порядок предметов, не опуская их под подложку.
- «Добавить предмет» принимает одно название и состояние. L/S и масштаб — текущей сцены.
- «Цветной/Монохромный» заменяет предоставленный исходник с сохранением трансформаций.

Если нет свободного места, команда не уменьшает предмет независимо и не двигает
соседей: сообщает ограничение. Лимит — 8 предметов плюс исходный фоновый дубль.
При движении/повороте панель не позволяет вывести предмет за холст. Перекрытия
при явной ручной правке допустимы; для их изменения доступны команды слоёв.

Поддерживается штатная правка в Figma; панель отслеживает актуальное выделение,
удаление и состав. После потери выделения снова выберите сцену/предмет. Пользовательские
вложенные группы нужно разгруппировать до уровня композиции для команд правки;
Auto Layout сцены отключить. Если предметы вручную приведены к разным масштабам,
добавление/дублирование блокируется до восстановления общих пропорций.
Смена состояния восстанавливает вложенную графику из исходника: ручные правки
отдельных контуров/цветов заменяются, но положение, поворот и размер сохраняются.

Проверка: собрать сцену → сдвинуть/повернуть → дублировать → сменить слой → удалить
копию → добавить монету → переключить состояние → удалить штатно в Figma.
Соседи/предыдущие фреймы должны оставаться неизменными. Проверить также чужое
выделение, ошибку неизвестного названия и отказ при нехватке места.

## Палитры — приёмка этапа 4

На вкладке «Палитра» доступны фиолетовая, оранжевая и бирюзовая схемы с образцами
восьми ролей. Выбор задаёт цвета следующей сборки; он не перекрашивает существующие
сцены автоматически. Чтобы изменить результат, выберите композицию/её предмет
и нажмите «Применить к выбранной композиции».

Перекраска меняет fills/strokes по исходным ролям, сохраняя размеры, матрицы,
непрозрачность, маски, порядок и ручное расположение. Форма подложки сохраняется:
встроенные схемы меняют цвета той же графики. Смена состояния, добавление и дубль
используют активную палитру сцены, а не исходную фиолетовую.

### Своя схема

1. Нажмите «Скачать JSON-пример», измените восемь HEX и задайте свой латинский id.
2. Загрузите файл (до 32 КБ). Новая схема появится в списке.
3. Для выбранной сцены нажмите «Применить»; либо перейдите в «Сборка» и создайте новую.

Готовый пример для проверки: [custom-palette.green.json](catalog/custom-palette.green.json).
Формат: schemaVersion=1, id, name, положительная целая version и восемь ролей colors:
surface, mid, deep, accentLight, accentStrong, accentSoft, ink, paper. Значения — #RRGGBB.
Назначения и права — [catalog/README.md](catalog/README.md). Внешний файл не может
изменять права ролей. Отсутствующие/неверные поля вызывают ошибку до изменения сцены.
Критические совпадения цветов отклоняются, низкий контраст/остальные совпадения отмечаются.

До 10 личных схем сохраняются для следующих запусков. Повторный импорт личного id
обновляет запись, не перекрашивая старые результаты. Сцена хранит свою полную схему:
её можно использовать после перезапуска и переноса документа без личного реестра.
Если хранилище недоступно, импорт действует в текущей сессии; применение всё равно
сохраняет палитру внутри документа. Встроенные id зарезервированы.

### Что проверить

- Собрать новую сцену в оранжевой схеме, затем применить бирюзовую → фиолетовую → оранжевую.
- Перед перекраской сдвинуть/повернуть предмет: трансформации и слои должны сохраниться.
- На оранжевой сцене сменить состояние предмета, добавить и дублировать: цвета не возвращаются к фиолетовым.
- Загрузить зелёный пример, применить и повторить эти действия, включая L/S и разные форматы.
- Перезапустить плагин и выбрать перекрашенную сцену: её схема должна восстановиться.
- Неверный HEX/неполная схема должны дать ошибку без частичной перекраски.

Исходные соответствия сохраняются в узлах: повторные замены не опираются на промежуточные HEX.
Ручные цвета при применении схемы восстанавливаются по этим ролям. Неизвестные новые
цвета без исходных ролей, изменённые наборы paints, изображения и связанные стили/
переменные отклоняются явно. Это поддержка нашей библиотеки, а не универсальная
перекраска произвольного SVG. Маски не перекрашиваются, strokes/gradient alpha сохраняются.

## Данные и ограничения

- assets/ — 40 SVG предметов, исходные фоны, три схемы и 18 примеров.
- catalog/ — основания размеров, роли цветов, политика углов, пример пользовательской палитры.
- core.ts — поиск и чистая компоновка/геометрия.
- editor.ts — команды и актуальный состав сцены.
- palette-core.ts / palette-figma.ts / palette-registry.ts — роли, перекраска и личные схемы.
- code.ts — Figma-адаптер, сообщения, импорт и события активной страницы.
- ui.html — панель; scripts/build.mjs — упаковка; tests/ — проверки.
- generated/ и code.js — результаты сборки, не редактировать вручную.

`ochen-plan` хранит происхождение генерации. `ochen-current-scene` — актуальные
экземпляры/состояния/слои/трансформации после команд и нативной правки.
Снимок использует локальные node ID экземпляров, а источник предмета задаётся
стабильным asset ID и путём каталога; это разные идентификаторы.

Активная палитра хранится в ochen-palette сцены, исходные paints узлов — в ochen-color-baseline.
При добавлении/смене состояния/дублировании применяется схема сцены.
Во вкладке **SVG** выберите «Подготовить SVG», затем ссылку скачивания. Экспортируется
выбранная сцена с текущими правками; после изменений подготовьте файл заново.
Каждый предмет получает отдельную группу с названием. Растр, внешние ресурсы,
повреждённые ссылки и потеря групп блокируют скачивание. Временная копия для
экспорта удаляется и при ошибке; исходная сцена не переименовывается.
Проверка XML в настоящем браузере: `npm.cmd run test:svg-browser` (требуется Chrome;
другой путь можно указать через CHROME_PATH). Повторный импорт в Figma проверяется вручную.
В 5A реализован подбор до 49 раскладок по заполнению, балансу, связности и читаемости.
Для сравнения до/после: `npm.cmd run preview:compositions` после сборки, затем открыть
out/composition-review-5a.html. В плагине выбрать «Автоматически» и собрать новую сцену;
существующие сцены не пересобираются. Требуется визуальная приёмка 5A, затем обсуждение метафор (6).
Публичное распространение выданной библиотеки отдельно не согласовано.
