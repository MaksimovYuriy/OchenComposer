# Ochen Composer

Плагин для **Figma Design**, автоматически собирающий векторные иллюстрации из
подготовленной библиотеки. Два сценария: подбор по метафоре/заголовку через ИИ
и сборка по названиям компонентов без сети. Формат плагина прямо допускается ТЗ.

Новые объекты не генерируются: используются предоставленные SVG. Перемещаются и
поворачиваются целые предметы, сохраняются относительные размеры, цвета меняются
по разрешённым ролям палитры.

**Репозиторий:** [github.com/MaksimovYuriy/OchenComposer](https://github.com/MaksimovYuriy/OchenComposer).
Перед отправкой необходимо опубликовать текущие изменения и проверить доступ
проверяющего. Наличие ссылки не подтверждает публикацию актуальной сборки.

## Запуск готовой сборки

1. Распакуйте `OchenComposer-review.zip`, откройте папку `OchenComposer`.
2. В **Figma Desktop** откройте редактируемый файл Figma Design.
3. Выберите **Plugins → Development → Import plugin from manifest…** и укажите
   `manifest.json` из распакованной папки.
4. Запустите **OchenComposer** из раздела Development.

В архиве уже есть `code.js` и `ui.html`. Node.js и сборка для запуска архива не нужны.
Библиотека встроена; доступ к исходному Figma-файлу кандидата не требуется.
Официальная инструкция: [импорт плагина для разработки](https://help.figma.com/hc/en-us/articles/360042786733-Create-a-classic-plugin-for-development).

## Сценарий 1 — метафора или заголовок

1. Во вкладке **Сборка** откройте **Настройки ИИ · OpenRouter**.
2. Создайте личный ключ на [OpenRouter](https://openrouter.ai/keys), вставьте его
   и нажмите **Проверить ключ**. Отдельное применение настроек тоже доступно.
3. Оставьте `openrouter/free`. Выберите **Метафора или описание сцены · ИИ**.
4. Введите **«Знания открывают возможности»** и нажмите **Собрать**.
5. Получите объяснение замысла и отдельный фрейм с композицией.

Другие запросы: **«Дать идее вырасти»**, **«Быть на одной волне»**. ИИ интерпретирует
смысл и выбирает подходящую выполнимую композицию. Буквальное совпадение с каждой
деталью фразы не требуется; существенную адаптацию модель объясняет.

Плагин проверяет JSON-план, компоненты, пространственные связи и геометрию, подбирает
общий масштаб и плотность. При ошибке плана — одна попытка исправления: **до двух
API-запросов на сборку**, каждый с ожиданием до 45 секунд. Ключ, сеть, квота и таймаут
не запускают автоматический повтор. **Новый вариант** в этом режиме запрашивает
новую интерпретацию и также расходует квоту.

`openrouter/free` выбирает доступную бесплатную модель, поэтому ответы могут
различаться. Можно указать конкретный ID с окончанием `:free`; платные ID плагин
отклоняет. Доступность и лимиты зависят от аккаунта и [условий OpenRouter](https://openrouter.ai/pricing).
Для проверки ИИ нужен собственный действующий ключ, он не входит в поставку.
Проверка ключа занимает до 10 секунд и проверяет авторизацию, а не качество модели.

## Сценарий 2 — названия компонентов

1. Выберите **Названия · без ИИ**.
2. Введите **«Книга, телефон, монета»**. Другие примеры: **«Лампа, книга, цветы»**,
   **«Папка, кошелёк, монета»**.
3. Выберите формат, детализацию L/S, схему компоновки и нажмите **Собрать**.
4. **Новый вариант** создаёт отдельный фрейм; предыдущая композиция сохраняется.

Этот сценарий работает без сети и ключа. До восьми предметов через запятую или
перенос строки; повтор названия добавляет экземпляр. Неизвестный компонент даёт
ошибку без частичного результата. Дополнительный монохромный дубль первого предмета
включён по умолчанию и отключается флажком. В режиме ИИ неявный дубль не добавляется.

**Каталог:** книга, телефон, монета, пазлы, цветы, ручка, папка, наушники, лампа,
кошелёк. **Форматы:** 1000×1000, 1200×630, 800×1200. **L/S** — отдельные исходники
с разной детализацией, а не два масштаба одного SVG.

## Правка, палитра и SVG

1. Выберите предмет или его внутреннюю деталь. Во вкладке **Правка** доступны
   перемещение, поворот, дублирование, удаление, слои, добавление предмета из каталога
   и переключение цветного/монохромного состояния.
2. Во вкладке **Палитра** выберите фиолетовую, оранжевую или бирюзовую схему
   и нажмите **Применить к выбранной композиции**.
3. Загрузите [пользовательскую палитру](catalog/custom-palette.green.json) и примените
   её. Для своей схемы скачайте JSON-пример из интерфейса и измените HEX по ролям.
4. Выберите сцену или предмет → **SVG → Подготовить SVG → Скачать**.
5. Перетащите скачанный файл обратно в Figma. Сравните внешний вид и возможность
   отдельно выбирать векторные предметы. Это финальная ручная проверка экспорта.

Править можно также штатными инструментами Figma. Команды копирования/добавления
сохраняют общий масштаб; при нехватке места операция отклоняется. Перекраска сохраняет
позиции и слои. После правок подготовьте SVG заново — ссылка содержит снимок состояния.

## Сравнение с ТЗ

| Требование | Реализовано |
| --- | --- |
| Запускаемый продукт | Плагин Figma Design, готовая сборка и manifest |
| Метафора/заголовок → композиция | OpenRouter → проверенный план → локальное исполнение |
| Названия → композиция | Каталог, синонимы, повторы, автоматические раскладки |
| Подготовленная SVG-библиотека | 40 предметных SVG: 10 компонентов × L/S × два состояния |
| Только предоставленные элементы | Исходники из assets/ встроены в сборку; ИИ не возвращает графику |
| Геометрия и относительные пропорции | Целые исходные предметы, один равномерный масштаб для всей сцены |
| Перенос, поворот, дубль, удаление, слои | Панель правки и нативные объекты Figma |
| Смешивание элементов | Общий каталог позволяет сочетать разные предоставленные компоненты |
| Размеры и детализация | Три формата холста и отдельные L/S-исходники |
| Главные и фоновые состояния | Цветные/монохромные варианты, автоматический выбор и ручное переключение |
| Палитры и автоматическая перекраска | Три схемы, импорт JSON с восемью ролями, перекраска текущей сцены |
| Ограничения цветов | Фон/монохром используют только фоновые роли; цветные объекты — все разрешённые роли |
| SVG-экспорт | Скачивание текущей сцены, проверка XML, размеров, ссылок и отдельных векторных групп |

Это описание функций, а не отметка о завершённой независимой приёмке. Генерацию через
API проверял владелец; весь набор метафор ещё не зафиксирован. Обратный импорт
экспорта в настоящую Figma и независимый запуск требуют финальной проверки.
Используется выданная библиотека; **соответствие элементов исходным 20 иллюстрациям
нужно подтвердить по исходным материалам**. Число 40 вариантов само по себе этого
не доказывает. Полная [матрица требований](docs/REQUIREMENTS.md).

## Архитектура: хранение, извлечение и переиспользование SVG

- **Хранение:** assets/ содержит SVG, catalog/ — палитры и правила. Сборка проверяет
  файлы и упаковывает их в generated/assets.ts с ID, размерами, детализацией и состоянием.
- **Извлечение:** по названиям выбираются записи каталога; для метафоры ИИ возвращает
  ID экземпляров и отношения. Валидатор допускает только существующие компоненты.
- **Переиспользование:** Figma Plugin API создаёт нативные векторные узлы из исходного
  SVG. Смена состояния загружает подготовленный вариант с сохранением трансформаций.
- **Цвета:** роли и исходные соответствия сохраняются; повторная перекраска не зависит
  от промежуточных HEX. Права фоновых и объектных ролей проверяются кодом.
- **Документ и экспорт:** сохраняются план генерации, текущий снимок и палитра.
  Временная копия текущего фрейма экспортируется в SVG с отдельными группами.
  Плагин не использует растровый снимок как результат.

Код разделён на composition/, scene/, ai/, palette/, plugin/, ui/.
Подробная [карта исходников и сборки](docs/ARCHITECTURE.md).

## AI-инструменты и данные

- **При разработке:** OpenAI Codex — код, рефакторинг, тесты, документация.
- **В продукте:** OpenRouter API и выбранная текстовая модель — интерпретация смысла
  и предложение композиции. Конкретная модель показывается после сборки;
  `openrouter/free` не фиксирует одного провайдера.
- Генерация новых иллюстративных объектов и изображений не применяется.

В API передаются фраза, текстовый каталог, правила с примерами JSON, размеры/углы
исходников и формат/seed. **SVG, изображения примеров и документ Figma не отправляются.**
Ключ используется для авторизации; по умолчанию живёт до закрытия плагина. Сохранение
на устройстве включается отдельно, есть удаление. Ключ не записывается в документ,
SVG или репозиторий. Локальное хранилище Figma не является защищённым менеджером
паролей. Обработка текста внешними сервисами подчиняется их условиям; нулевое
хранение не обещается.

## Сборка из исходников

Нужны Node.js 22+ и npm:

```sh
npm ci
npm run build
npm run lint
npm test
```

На Windows при блокировке npm.ps1 используйте `npm.cmd`. Тесты сначала пересобирают
проект. `npm run watch` отслеживает исходники. Корневые code.js и ui.html генерируются;
панель редактируется в src/ui/.

```sh
npm run examples
npm run test:svg-browser -- --examples
npm run package
```

Браузерная проверка требует Chrome; другой путь задаётся через `CHROME_PATH`.
Команда package собирает плагин, создаёт примеры и **dist/OchenComposer-review.zip**
с готовым плагином и исходниками. Исключены node_modules/, .git/, out/, .env и
временные файлы. Рядом — dist/package-manifest.json с перечнем файлов и SHA-256.

## Как передать на проверку

Передайте **ссылку на архив**, **ссылку на актуальный репозиторий**, **короткую
демонстрацию** и три SVG-примера. Архив запускается по инструкции выше без сборки.
Для выбранного формата не нужен отдельный сайт: по ТЗ допустим запускаемый плагин.

Контрольный лист и сценарий демонстрации: [docs/SUBMISSION.md](docs/SUBMISSION.md).
Видеозапись, публикация архива и финальные ручные проверки автоматически не выполнены.
Подробное руководство по операциям: [docs/USER_GUIDE.md](docs/USER_GUIDE.md).

## Ограничения

- Фиксированный предоставленный каталог, максимум восемь выбранных предметов.
  Импорт произвольных SVG не реализован; ТЗ допускает заранее подготовленную библиотеку.
- ИИ интерпретирует замысел, не гарантируя буквальную сцену. Своя модель, сервер
  и личная база рецептов в эту поставку не входят.
- Опоры — книга/папка, один уровень вложенности. Новые ракурсы, зеркалирование,
  растяжение и редактирование контуров не поддерживаются.
- Перекрытия разрешены для опор; их проверка основана на прямоугольных границах,
  а не физической поверхности предмета.
- Нативная Figma позволяет вручную изменить геометрию и нарушить ТЗ. Плагин не
  блокирует весь редактор и не поддерживает произвольную переделку внутренних
  контуров, Auto Layout и пользовательских вложенных групп.
- SVG сохраняет векторные предметы и группы; статус Figma-компонентов, instances
  и связи с библиотекой компонентов при экспорте не обещаются.
