Источники: [ORIGINAL_BRIEF.md](ORIGINAL_BRIEF.md), [REQUIREMENTS.md](REQUIREMENTS.md).
Этот файл заменяет прежнюю очередь; добавлены пропущенные повороты и операции правки.

## Цикл работы

**Итерация → приёмка владельцем → исправление замечаний → повторная проверка → следующая итерация.**

- Выполнять одну поставку, не начинать следующую без приёмки/прямого разрешения.
- Перед проверкой дать точный сценарий, автоматические результаты и ограничения.
- Не подменять автоматическую функцию наличием ручного инструмента Figma.
- Не объявлять приёмку по тестам или своему рендеру. Реализация, тест и приёмка
  имеют отдельные статусы. Исправления входят в ту же итерацию.
- Не скрывать явно запрошенные предметы, не терять ручные правки и предыдущие результаты.
- Блокирующие дефекты: неверный состав, искажения, недопустимые цвета, потерянные
  правки, растр, сбой, отсутствие обязательной операции. С ними поставка не принята.
- До реализации метафор обязательно отдельно обсудить подход. Не подключать AI заранее.

## 3B. Автоматическая компоновка с поворотами

**Цель:** автоматизация включает добавление, расположение, подходящие повороты,
цветные/монохромные состояния и порядок слоёв; не только координаты прямоугольников.

### Реализация

1. Добавить rotation/опорную точку в план сцены и политики допустимых углов
   для объектов/шаблонов. Значения выбрать по просмотру исходников и примеров.
2. Рассчитывать поворот самим алгоритмом с воспроизводимым seed; применять
   матрицей к готовому SVG-контейнеру, не редактируя paths.
3. Рассчитывать границы и перекрытия после поворота. Общий scale сохраняется;
   при нехватке места изменить размещение/общий масштаб или сообщить ограничение.
4. Разделить смысловой фокус, цветовое состояние и принадлежность к фоновому дублю.
   Сделать понятную политику состояний при сборке и режим без монохромных предметов.
5. Проверить соответствие каталога выданным исходникам и документировать доступное
   происхождение; смешать в демо элементы разных исходных иллюстраций.

### Приёмка

- [ ] Ненулевой поворот появляется в согласованных тестовых композициях **без
      ручного вращения**. Не каждый предмет обязан вращаться и не каждый seed ненулевой.
- [ ] Углы допустимы для предмета; исходная изометрия/тени не дают визуально нелепых результатов.
- [ ] Локальные размеры/общий scale не меняют относительные пропорции при вращении.
- [ ] Повёрнутые предметы не обрезаны и не скрывают смысловые части друг друга.
- [ ] Одинаковые вход/план/seed воспроизводят положение, угол, состояние и слои.
- [ ] Смена seed даёт различие; явно запрошенный состав не меняется.
- [ ] Есть сборка с монохромными предметами и без них; настройки объясняют дубли.
- [ ] Три контрольных набора × три формата × L/S проходят визуальную проверку.
      Проверены дополнительно один, повторяющиеся и восемь предметов.
- [ ] После автоматического поворота переключение состояния туда-обратно сохраняет его.
- [ ] Продемонстрирована сцена с элементами разных исходных иллюстраций;
      пробелы в сведениях о происхождении перечислены, не выдуманы.

**Автоматически:** детерминизм углов, матрицы, повернутые границы/перекрытия,
общие коэффициенты, точный состав, регрессия 3A.
**Приёмка:** владелец проверяет именно автоматические повороты и качество композиции.

## 3C. Управление предметами и слоями

**Цель:** все перечисленные операции доступны как команды панели к объектам Figma.
Это принятое полное покрытие операций; отдельный редактор холста не создаём.

- [ ] В существующую выбранную композицию можно добавить известный предмет,
      выбрав детализацию/состояние; использовать масштаб сцены. Не пересобирать остальные.
- [ ] Выбранный предмет можно сдвинуть и повернуть командой панели с понятным
      направлением/значением. Поворот не деформирует и не меняет локальные размеры.
- [ ] Дублирование добавляет ровно один экземпляр с тем же масштабом, состоянием,
      палитрой и поворотом; смещение не прячет копию под оригиналом.
- [ ] Удаление убирает только выбранный экземпляр. Другие предметы/фон не пересобираются.
- [ ] «Выше/ниже» меняет порядок в своей композиции; фон не становится случайно передним.
- [ ] Штатные move/rotate/duplicate/delete/reorder в Figma также работают.
- [ ] Удаление выбранного предмета штатно в Figma не оставляет устаревшее активное
      выделение в панели. Чужая графика не изменяется.
- [ ] Команды корректно работают с повёрнутыми и монохромными предметами;
      не меняют seed/исходный состав сохранённого результата скрытой пересборкой.
- [ ] Лимиты добавления/дублирования объясняются; при нехватке места не нарушать
      пропорции и не масштабировать только добавленный предмет.
- [ ] Метаданные текущей сцены учитывают добавления, удаления, дубли и состояния;
      исходный план генерации отделён от актуального состава.

**Автоматически:** точная область команды, число экземпляров, порядок, трансформации,
потерянное выделение и обработка ошибок. **Приёмка:** весь набор команд в Figma.

## 4. Палитры и перекраска

- [ ] Три исходные схемы переключаются с автоматической перекраской предметов и фона.
- [ ] Четвёртая схема подключается данными без новой ветки алгоритма.
- [ ] Пользователь загружает JSON с ролями; формат и пример доступны в интерфейсе/README.
- [ ] Ошибки файла, HEX, обязательных ролей, версии дают понятное сообщение до изменений.
- [ ] Фоновые цвета разрешены в предметах; объектные роли не попадают в подложку/декор фона.
- [ ] Монохромные состояния следуют фоновым ролям. Контуры, белые детали и соседние
      части не исчезают. Подозрительный контраст обрабатывается явно.
- [ ] A → B → A воспроизводит исходные соответствия, без накопления замен.
- [ ] Перекраска сохраняет позиции, автоматические/ручные углы, общий масштаб и слои.
- [ ] Смена состояния после перекраски сохраняет активную схему.
- [ ] Дубли/добавленные предметы получают текущую схему; другие композиции не меняются.
- [ ] Проверены L/S, все три формата, main/background, исходные и пользовательская схемы.

**Автоматически:** права ролей, формат загрузки, повторные замены, комбинации
с состояниями/командами. **Приёмка:** визуально три встроенные и одна загруженная палитра.

## 5. Экспорт и законченный сценарий названий

- [ ] SVG скачивается из панели для явно выбранной композиции, включая после перезапуска.
- [ ] Экспорт отражает текущее состояние после поворотов, смены схемы/состояния,
      ручных правок, дублирования, удаления и перестановки слоёв.
- [ ] XML/viewBox/локальные ссылки корректны; нет неожиданных image и внешних ресурсов.
- [ ] Повторный импорт сохраняет внешний вид, порядок, повороты и отдельные предметы.
- [ ] Ошибки выбора, удалённый фрейм, сбой экспорта/импорта не разрушают сцену.
- [ ] При ошибке сборки удаляется только собственный незавершённый результат.
- [ ] Названия → автоматическая композиция с поворотами → команды правки → палитра
      → скачивание → повторный импорт пройдены без модели/сети.
- [ ] Чистая сборка и запуск по README возможны без файла/аккаунта владельца.

**Автоматически:** структура SVG и регрессия сцены. **Приёмка:** полный второй сценарий.

1. Перезапустить плагин, создать новую сцену «Книга, телефон, монета», диагональ,

6. Выбрать автоматически повёрнутый предмет и переключить его состояние туда/обратно:

7. Проверить один, повторяющиеся и восемь предметов; оценить читаемость и отсутствие обрезки.
8. Сообщить замечания или приёмку. После фиксов перейти к 3C, палитры пока не начинать.
